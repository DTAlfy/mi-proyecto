# Handshake

**Resumen:** Implementa una fase obligatoria de alineación antes de ejecutar cualquier proyecto o generar la solución final. El objetivo es llegar a un entendimiento perfecto de la idea del usuario, tapar "hoyos" u omisiones, y evitar retrabajos.

## Cuándo usarlo

- Cuando el usuario mencione explícitamente hacer un "handshake".
- Cuando el usuario presente una idea para un proyecto nuevo (aplicación, código, diseño, etc.) que requiera desarrollo paso a paso.

## Pasos

1. **Pausa la ejecución:** Bajo ninguna circunstancia entregues la solución final, el código o el producto terminado en tu primera respuesta.
2. **Análisis de vacíos:** Evalúa la idea inicial. Identifica dudas, falta de contexto, casos borde o variables que el usuario no haya considerado.
3. **Validación inversa:** Hazle al usuario las preguntas necesarias para aclarar el panorama (entorno, restricciones, formato esperado, etc.).
4. **Resumen y confirmación:** Una vez que el usuario responda, redacta un breve resumen del entendimiento del proyecto.
5. **Cierre del handshake:** Confirma que el "handshake" está completo y declara que estás listo para comenzar la ejecución real cuando el usuario lo indique.

## Precauciones

- No abrumes al usuario con una lista interminable de preguntas; enfócate en las 3-5 más críticas para empezar.
- Si el usuario da una instrucción directa y sencilla que no requiere planificación, advierte brevemente que te saltarás el handshake para mayor agilidad, a menos que indique lo contrario.
